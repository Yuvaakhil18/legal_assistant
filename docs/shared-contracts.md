# Shared Contracts & Domain Model Architecture

This document defines the canonical TypeScript shared contracts implemented under `backend/src/types/`. These types serve as the definitive boundary definitions across all 7 specialized agents.

## 1. Domain Types Overview

### 1.1 Document (`document.ts`)
*   **Domain Types:** `DocumentMetadata`, `DocumentArtifact`, `DocumentStatus`, `DocumentProcessingState`
*   **Ownership:** `IngestionAgent`
*   **Producer:** `IngestionAgent` (creation and validation)
*   **Consumer:** All downstream agents (read-only)
*   **Lifecycle:** Created upon file upload -> Transitions through `queued` -> `processing` -> `analyzed` (or `failed`).
*   **Serialization Boundaries:** Exposed entirely via `/api/documents/:id` REST endpoints.
*   **Persisted Fields:** All `DocumentArtifact` and `DocumentMetadata` fields are persisted in the `documents` table.
*   **Internal-Only Fields:** `progress_percentage` within `DocumentProcessingState` is primarily for Redis/BullMQ ephemeral tracking.

### 1.2 Clause (`clause.ts`)
*   **Domain Types:** `Clause`, `ClauseType`, `ClauseArtifact`, `ClauseLocation`
*   **Ownership:** `IngestionAgent` (creation), `RetrievalAgent` (classification)
*   **Producer:** `IngestionAgent`
*   **Consumer:** `RetrievalAgent`, `RiskAuditorAgent`, `LegalInquiryAgent`
*   **Lifecycle:** Created during document segmentation -> Augmented with `ClauseType` -> Embedded and compared.
*   **Serialization Boundaries:** Shared between BullMQ workers; mapped directly to the `clauses` database table.
*   **Persisted Fields:** `raw_text`, `tokenized_text`, `sha256`, `category`, `location` mapping (`clause_index`, `section_number`).
*   **Internal-Only Fields:** `tokenized_text` is internal for processing and reverse-substitution; it should generally not leak to the frontend.

### 1.3 Retrieval (`retrieval.ts`)
*   **Domain Types:** `EmbeddingRequest`, `EmbeddingResult`, `BenchmarkClause`, `BenchmarkMatch`, `RetrievalResult`
*   **Ownership:** `RetrievalAgent`
*   **Producer:** `RetrievalAgent`
*   **Consumer:** `RiskAuditorAgent`
*   **Lifecycle:** Short-lived requests to vector store -> Yields `RetrievalResult` containing benchmark matches.
*   **Serialization Boundaries:** Defines the HNSW pgvector inputs/outputs.
*   **Persisted Fields:** `BenchmarkClause` is persisted in `benchmark_clauses`; `BenchmarkMatch` data influences the `clause_benchmarks` join table.
*   **Internal-Only Fields:** `EmbeddingRequest` and `EmbeddingResult` (including float vectors) are strictly backend/internal cache.

### 1.4 Risk (`risk.ts`)
*   **Domain Types:** `RiskLevel`, `RiskAssessment`, `SemanticDelta`, `EvidenceReference`
*   **Ownership:** `RiskAuditorAgent`
*   **Producer:** `RiskAuditorAgent`
*   **Consumer:** `CounterDraftAgent`, `GotchasAgent`
*   **Lifecycle:** Generated by evaluating `RetrievalResult` against a `ClauseArtifact` -> Appended to database.
*   **Serialization Boundaries:** Shapes the prompt schema enforcement (Gemini output validation).
*   **Persisted Fields:** All fields map to the `clauses` table columns (e.g., `risk_level`, `confidence_score`, `deviation_summary`, `risk_factors`).
*   **Internal-Only Fields:** Intermediate `EvidenceReference` arrays may remain internal unless specifically surfaced in the Gotchas report.

### 1.5 Legal (`legal.ts`)
*   **Domain Types:** `Gotcha`, `ChecklistItem`, `AttorneyBrief`, `CounterDraft`, `GuardrailResult`
*   **Ownership:** `CounterDraftAgent`, `GotchasAgent`, `GuardrailAgent`
*   **Producer:** Respective agents.
*   **Consumer:** Frontend UI, `LegalInquiryAgent`
*   **Lifecycle:** Final synthesis outputs generated after all clauses are evaluated -> Sanitized by `GuardrailAgent`.
*   **Serialization Boundaries:** Represents the bulk payload of the `/api/documents/:id/audit` endpoint.
*   **Persisted Fields:** `Gotcha`, `ChecklistItem`, `AttorneyBrief`, `CounterDraft` are natively stored in their respective tables.
*   **Internal-Only Fields:** `GuardrailResult` is an internal validation flag; it does not persist, it merely gates the output.

### 1.6 Query (`query.ts`)
*   **Domain Types:** `DocumentQuery`, `QueryCitation`, `QueryResponse`
*   **Ownership:** `LegalInquiryAgent`
*   **Producer:** `LegalInquiryAgent` (response), Frontend (query)
*   **Consumer:** Frontend
*   **Lifecycle:** Ephemeral synchronous RAG request -> Stores log in `document_qas` -> Returns answer.
*   **Serialization Boundaries:** Exact contract for `POST /api/documents/:id/query`.
*   **Persisted Fields:** The entire transaction is logged to `document_qas`.
*   **Internal-Only Fields:** `metrics` (token consumption) might be internally tracked for billing but optionally omitted in the client response envelope.

### 1.7 Jobs (`jobs.ts`)
*   **Domain Types:** `AnalysisJob`, `JobStatus`, `JobResult`
*   **Ownership:** BullMQ Dispatcher
*   **Producer:** BullMQ / Redis
*   **Consumer:** Worker nodes, Polling clients.
*   **Lifecycle:** Asynchronous processing queues (`pending` -> `active` -> `completed` / `failed`).
*   **Serialization Boundaries:** Used natively by Redis queues.
*   **Persisted Fields:** Managed ephemerally in Redis; not stored in PostgreSQL.
*   **Internal-Only Fields:** Fully internal backend infrastructure; the frontend receives synthesized progress via polling `doc:status`.

## 2. Validation and Constraints

- **Zod schemas** dictate the definitive schema definitions. TypeScript types are generated using `z.infer<>`.
- The strict adherence ensures zero mismatch between Agent outputs (LLM structured outputs), BullMQ worker parameters, and Postgres data types.
